ระบบเชื่อมโยงข้อมูลการส่งสินค้า ACA (Carriage) ไปยัง WD

เอกสารรายละเอียดขั้นตอนการทำงาน โครงสร้างข้อมูล ตารางฐานข้อมูล และข้อกำหนดรูปแบบไฟล์นำออก (CSV)

ภาพรวม ภาพรวมและการทำงานของระบบ

สคริปต์ **ACA (Carriage)** ทำหน้าที่ประมวลผลเบื้องหลังเพื่อดึงข้อมูลสรุปการส่งสินค้า (Shipment Confirm) ของใบสั่งส่งสินค้า (Delivery Order - DO) ในวันที่ระบุ โดยจะคัดกรองเฉพาะ DO ที่มีประเภทเป็น PRB หรือ BPI ตรวจสอบความถูกต้องของจำนวนสินค้า และอัปโหลดไฟล์ข้อมูลที่มีโครงสร้างมาตรฐานไปยังระบบของ Western Digital Corporation (WDC) ผ่าน SFTP (sftp2.wdc.com)

ขั้นตอนการทำงานหลัก:

  • DO Classification (การจัดกลุ่ม DO): อ่านรายการการยืนยันการส่งสินค้าตามวันที่ระบุ และใช้รหัสคำนำหน้า (Prefix) เพื่อคัดแยกประเภทการขนส่งว่าเป็นแบบส่งตรง (Direct) หรือส่งผ่านคลังสินค้ากลาง (Hub)
  • Data Aggregation (การรวบรวมข้อมูล): ดึงข้อมูลจากตาราง WMS และฐานข้อมูลการบรรจุสินค้า (Packaging/Match Data) เพื่อรวบรวมรายละเอียดพาเลท (Pallet), กล่องสินค้า (Box), และรหัสถาดบรรจุ (Tray Barcode)
  • Expiry Date Derivation (การคำนวณวันหมดอายุ): คำนวณหาวันหมดอายุขั้นต่ำ (Minimum Expiry Date) ของถาดบรรจุในลอตนั้นๆ โดยอ้างอิงจากวันที่ในรหัสกล่องหรือ PackKey
  • Validation (การตรวจสอบข้อมูล): ตรวจสอบว่าจำนวนสินค้าที่ระบุในการแพ็ก (Pack Qty) เท่ากับจำนวนสินค้าในใบแจ้งหนี้/ใบสั่งส่งสินค้า (Shipment Qty) หรือไม่ หากไม่ตรงกันระบบจะส่งอีเมลเตือนและยุติการส่งข้อมูล
  • Transmission (การจัดส่งข้อมูล): เขียนไฟล์ข้อมูลออกเป็นไฟล์ CSV จากนั้นสำรองไปยังประวัติ QE และทำการอัปโหลดผ่าน SFTP ไปยัง WDC ปลายทางด้วยคีย์การเชื่อมต่อเฉพาะ (Belton_Carriage.ppk)

ตาราง โครงสร้างและรายละเอียดตารางฐานข้อมูล

รายละเอียดโครงสร้างตารางฐานข้อมูลภายในระบบ WMS และฐานข้อมูลสายการผลิตที่ใช้ในการอ้างอิงข้อมูล ACA

1. WMS.HGSTACA_SHIP_CONFIRM ▼

เก็บข้อมูลประวัติการยืนยันการจัดส่งสินค้าเพื่อดึงหมายเลข DO (Delivery Order) ประจำวัน

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
doVARCHARเลขที่ใบสั่งส่งสินค้า / ใบกำกับสินค้า (DO Number)
plan_idVARCHARหมายเลขแผนงานการจัดส่ง (Shipment Plan ID)
pallet_noVARCHARรหัสพาเลทสินค้า (Pallet Number)
box_detailVARCHARข้อมูลบาร์โค้ดกล่องและรายละเอียดสินค้า
dateDATETIMEวันที่บันทึกการยืนยันจัดส่ง
typeVARCHARประเภทธุรกรรม (กำหนดดึงเฉพาะ 'PACK')
qtyINTจำนวนชิ้นงานในการส่งลอตนั้นๆ
2. WMS.HGSTACA_SHIP_TO_MASTER ▼

ตารางบันทึกปลายทางจัดส่งและรหัสประเภทปลายทางโดยอ้างอิงจากตัวอักษรนำหน้าของ DO

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
prefixVARCHARตัวอักษรนำหน้า 4 ตัวแรกของรหัส DO
ship_toVARCHARรหัสที่ตั้งคลังสินค้าปลายทางของ WDC
typeVARCHARประเภทของการขนส่ง (เช่น 'PRB' หรือ 'BPI')
statusVARCHARสถานะการใช้งานคีย์ปลายทาง (ดึงเฉพาะ 'active')
3. WMS.HGSTACA_MATCH_DATA ▼

ตารางเชื่อมโยงในระบบ WMS สำหรับเชื่อมระหว่างใบกำกับสินค้า (DO) และหมายเลขคลังจัดเก็บผลิต (Store Lot / Production Lot)

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
do_noVARCHARหมายเลข DO อ้างอิง
store_lotVARCHARหมายเลขที่ตั้งจัดเก็บชิ้นงานในคลัง (Store Lot)
prod_lotVARCHARหมายเลขลอตการผลิตจากโรงงาน (Production Lot)
box_noVARCHARหมายเลขลำดับกล่องสินค้า
4. HGSTACA.PACK_HEADER (ฐานข้อมูลเครื่องจักร: HGSTACA02) ▼

ข้อมูลที่ดึงมาจากฐานข้อมูลฝั่งผลิตเครื่องสแกนบาร์โค้ดของโรงงาน

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
pack_idVARCHARหมายเลขการสแกนกล่องบรรจุภัณฑ์ (Pack ID)
tot_qty_packINTจำนวนชิ้นงานรวมในแพ็กนั้นๆ
barcodeVARCHARรหัสบาร์โค้ดถาดบรรจุ (Tray ID)
5. WMS.HGSTACA_RUNNING_TRANSFER_CUSTOMER ▼

ตารางเก็บตัวนับลำดับการอัปโหลดไฟล์ (Running counter) สำหรับระบุในฟิลด์ชื่อไฟล์

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
running_transferINTลำดับเลขวิ่ง (001 - 999) เมื่อถึง 999 จะหมุนกลับมาเริ่มที่ 1 ใหม่อัตโนมัติ
ตรรกะ ขั้นตอนการประมวลผลและการทำงานโดยละเอียด

การดึงและคัดแยกกลุ่มข้อมูล DO

สคริปต์เริ่มต้นจะเรียกใช้ข้อมูล DO ประจำวันผ่านฟังก์ชัน: 

$aDOdata = getDO($current_date);

จากนั้นระบบจะวิเคราะห์คีย์นำหน้า 4 ตัวแรก (DO Prefix) จากตาราง Master เพื่อคัดแยกลำดับการทำงานดังนี้:

  • ประเภท PRB: ตรวจสอบคอลัมน์ ship_to_location. หากมีค่าเป็น 'VMI-Hub' จะเก็บไว้ในกลุ่ม Hub ($do_prb_hub) หากไม่ใช่จะคัดแยกเป็นกลุ่มส่งตรง ($do_prb_direct)
  • ประเภท BPI: เก็บไว้ในตัวแปรกลุ่มส่งตรง ($do_bpi_direct) และเรียกใช้โปรแกรมในลักษณะ Hub ปลายทาง

การเชื่อมโยงข้อมูลหลายมิติเพื่อออกรายงาน

เมื่อเข้าสู่ฟังก์ชัน gen_data_and_send_file() โปรแกรมจะทำการดึงข้อมูลเชื่อมโยงย้อนหลังตามลำดับ:

  1. getProdWMS($do_list): ดึงข้อมูลเชื่อมโยงใบกำกับสินค้า, รหัสลอตจัดเก็บ (Store Lot) และลอตผลิตจริง (Prod Lot)
  2. getShip_confirm_data($prod_lots): ดึงประวัติและวันที่ระบุในการขนส่ง รวมถึงรหัสพาเลท และจำนวนกล่องชิ้นงานในระบบจัดส่ง
  3. getPackWMS($store_lots): เชื่อมโยงรหัสกล่องและบรรจุภัณฑ์เพื่อหาหมายเลขการจัดกลุ่มแพ็ก (Pack ID)
  4. getPack($pack_list): เชื่อมโยงไปยังฐานข้อมูลสายผลิตเครื่องสแกน HGSTACA02 เพื่อรวบรวมบาร์โค้ดถาดบรรจุ (Tray Barcode ID) และจำนวนที่บรรจุสแกนจริง

ขั้นตอนการคำนวณวันหมดอายุชิ้นงานอย่างยืดหยุ่น

ระบบของ WDC กำหนดให้ใส่ข้อมูลวันหมดอายุสินค้าในคอลัมน์หมายเหตุ (Remark) โดยการถอดรหัสวันที่จาก PackKey: 

// 1. ดึงข้อมูล 6 หลักจากตัวแปร PackKey ตั้งแต่ตำแหน่งที่ 4 ซึ่งระบุปีเดือนวันในรูปแบบ YYMMDD
$date_string = substr($PackKey, 4, 6); // เช่น "250707" -> ปี: 25, เดือน: 07, วัน: 07

// 2. ปรับโครงสร้างปี ค.ศ. ให้เต็มรูปแบบ และบวกวันหมดอายุเพิ่มขึ้น 2 ปี
$full_year = (intval($year_short) + 2000) + 2; // เช่น 2025 + 2 = 2027

// 3. จัดการกรณีปีอธิกสุรทิน (Leap Year) หากวันที่คือ 29 กุมภาพันธ์ แต่ปีหมดอายุไม่มีวันที่ 29 ให้ปัดวันลงเป็น 28
if ($month == '02' && $day == '29' && !checkdate(2, 29, $full_year)) {
    $day = '28'; 
}
$current_expire_date_str = "{$full_year}-{$month}-{$day}";

// 4. ทำการกรองและเปรียบเทียบในระดับกลุ่ม (เปรียบเทียบคีย์นำหน้า 7 หลักแรก) เพื่อหาค่าวันที่ "น้อยที่สุด" เป็นวันหมดอายุลอต
// 5. จัดรูปแบบเพื่อส่งออกเป็นรูปแบบ "d-F-Y" (เช่น 07-July-2027) ลงในคอลัมน์ Remark

การเขียนบันทึกและการโอนถ่ายข้อมูลผ่าน SFTP

ขั้นตอนเมื่อผลรวมยอดสินค้าตรวจสอบความถูกต้องเรียบร้อยแล้ว:

  • การเขียนไฟล์ท้องถิ่น: เปิดสตรีมเขียนไฟล์ในระบบเซิร์ฟเวอร์ย้อนหลังไว้ที่โฟลเดอร์ /file_bit_log/
  • สำรองประวัติ QE: คัดลอกไฟล์ไปยังไดเรกทอรีตรวจสอบความสมบูรณ์ /file_bit_qe/
  • ส่งข้อมูล SFTP: ล็อกอินและส่งไฟล์ขึ้นระบบคลาวด์ของลูกค้าที่ sftp2.wdc.com โดยล็อกอินภายใต้ชื่อผู้ใช้ Belton_Carriage และกุญแจยืนยันตน Belton_Carriage.ppk
  • ล็อกสถานะเสร็จสิ้น: ปรับเพิ่มหมายเลขเลขวิ่ง Running ใน WMS และทำการเพิ่มรายการหมายเลข DO ที่ทำงานสำเร็จลงในตารางประวัติ WMS.HGSTACA_TRANSFER_DATA_LOG เพื่อป้องกันการประมวลผลซ้ำซ้อน
ส่งออก ข้อกำหนดโครงสร้างชื่อไฟล์และรูปแบบข้อมูล CSV

กฎการตั้งชื่อไฟล์ส่งออก (Filename Rule)

{Prefix}_{Type}_{YYYYMMDD}_000000_BEL_CARRIAGE_{ModelName}_{RunningNo}.csv

ตัวอย่างชื่อไฟล์จริง: Z0004_PRB_20260810_000000_BEL_CARRIAGE_ModelX_001.csv
รหัสคีย์นำหน้าไฟล์: S0004 (กรณีคลังสินค้าปลายทางแบบ Hub) หรือ Z0004 (กรณีจัดส่งแบบตรง Direct)
