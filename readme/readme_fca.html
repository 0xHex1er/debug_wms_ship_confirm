เอกสารอ้างอิง v1.0

ระบบเชื่อมโยงข้อมูลการส่งสินค้า FCA (Flex) ไปยัง WD

เอกสารรายละเอียดขั้นตอนการทำงาน โครงสร้างข้อมูล ตารางฐานข้อมูล และข้อกำหนดรูปแบบไฟล์นำออก (CSV)

ภาพรวม ภาพรวมและการทำงานของระบบ

สคริปต์ **FCA (Flex)** ทำหน้าที่ดึงข้อมูลสรุปการส่งสินค้า (Shipment Confirm) ของใบสั่งส่งสินค้า (Delivery Order - DO) ในวันที่กำหนด โดยจะทำการสืบค้นข้อมูลใบยืนยันการจัดส่งสินค้า คัดแยกประเภทปลายทางของลูกค้าตามกลุ่มรหัส Prefix คิวรีรายละเอียดกล่องพาเลท และการแพ็กเกจผลิตจากฐานข้อมูลกลางของ Hitachi โดยตรง เพื่อจัดรูปแบบและจัดส่งอัปโหลดไฟล์ไปที่บอร์ดของ Western Digital Corporation (WDC) ผ่าน SFTP (sftp2.wdc.com)

จุดที่แตกต่างอย่างมีนัยสำคัญจากระบบ ACA:
  • การกรองจำกัดช่องทาง: เส้นทางการประมวลผลของ PRB ทั้งหมดถูกปิดใช้งานไว้ (Comment out) ในโค้ดตัวดำเนินการปัจจุบัน โดยสคริปต์จะกรองและทรานสเฟอร์ข้อมูลเฉพาะรายการกลุ่ม BPI Direct เท่านั้น
  • ฐานข้อมูลที่เรียกใช้: ทำงานเชื่อมโยงบนตารางของ Flex / Hitachi (HIT_*) แทนที่ระบบ ACA เดิมที่เป็นของ Carriage
  • ความสัมพันธ์ถาดบรรจุที่สั้นลง: เรียกใช้ประวัติจากตาราง PROD_DATA ของระบบฝั่ง Hitachi คีย์โดยตรงด้วยรหัส prod_lot ทำให้ไม่จำเป็นต้องผ่านตารางจับคู่วัสดุระดับกลาง (WMS FGREC Box/Pack)
  • คอลัมน์ชื่อรุ่น (Build Name): มีการดึงค่าจากฟิลด์หมายเหตุ WMS.HIT_FGREC_DATA.remark ไปเขียนลงในคอลัมน์ Build Name ของ CSV ในขณะที่ ACA ปล่อยเป็นค่าว่าง
  • ไม่มีการคำนวณวันหมดอายุ: ในฟิลด์ Remark สำหรับส่งออกเป็นวันหมดอายุของ FCA ถูกกำหนดให้ปล่อยเป็นค่าว่างเปล่า ('') ไม่คำนวณจาก PackKey แบบ ACA
  • กุญแจความปลอดภัย SFTP: ล็อกอินเข้าใช้งานด้วยบัญชีผู้ใช้ Belton และคีย์การยืนยันตน Belton.ppk

ตาราง โครงสร้างและรายละเอียดตารางฐานข้อมูล

รายละเอียดตารางฐานข้อมูลภายในระบบ WMS และฐานข้อมูลสายการผลิตที่ใช้ในการอ้างอิงข้อมูล FCA

1. WMS.HIT_SHIP_CONFIRM ▼

เก็บประวัติการยืนยันจัดส่งสินค้าของผลิตภัณฑ์สาย Flex เพื่อดึงใบสั่งส่งของประจำวัน โดยกรองเฉพาะรายการที่ยังไม่ถูกส่ง (ไม่ปรากฏในประวัติ Log)

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
doVARCHARเลขที่ใบสั่งส่งสินค้า / ใบกำกับสินค้า (DO Number)
plan_idVARCHARหมายเลขแผนงานการจัดส่ง (Shipment Plan ID)
pallet_noVARCHARรหัสพาเลทสินค้า (Pallet Number)
box_detailVARCHARข้อมูลบาร์โค้ดกล่องและรายละเอียดสินค้า
dateDATETIMEวันที่บันทึกการยืนยันจัดส่ง
typeVARCHARประเภทธุรกรรม (กำหนดดึงเฉพาะ 'PACK')
2. WMS.HIT_SHIP_TO_MASTER ▼

ตารางบันทึกปลายทางจัดส่งและรหัสประเภทปลายทางโดยอ้างอิงจากตัวอักษรนำหน้าของ DO สำหรับสาย Flex

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
prefixVARCHARตัวอักษรนำหน้า 4 ตัวแรกของรหัส DO
ship_toVARCHARรหัสที่ตั้งคลังสินค้าปลายทางของ WDC
typeVARCHARประเภทของการขนส่ง (เช่น 'PRB' หรือ 'BPI')
statusVARCHARสถานะการใช้งานปลายทาง (ดึงเฉพาะ 'active')
3. WMS.SHIPMENTPALLET_BOX_PROD_HTC ▼

ตารางเชื่อมโยงระดับ WMS สำหรับเชื่อมโยงหมายเลขแผนจัดจัดส่งของ Flex เข้ากับลอตผลิต (Production Lot) และลอตจัดเก็บคลังสินค้า (Store Lot)

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
plan_idVARCHARหมายเลขแผนการส่งออก
store_lotVARCHARหมายเลขลอตคลังสินค้า (Store Lot)
prod_lotVARCHARหมายเลขลอตการผลิตจริง (Production Lot)
qtyINTจำนวนกล่องชิ้นงาน
4. HITACHI.PROD_DATA (ฐานข้อมูลฝั่งผลิต: HITACHI02) ▼

ข้อมูลที่อยู่บนเครื่องสแกนบาร์โค้ดของโรงงานฝั่ง Flex

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
prod_lotVARCHARหมายเลขลอตผลิตอ้างอิงหลัก
pack_idVARCHARรหัสหมายเลขอ้างอิงการแพ็กเกจบรรจุ
5. WMS.HIT_FGREC_DATA ▼

ตารางระบบ WMS ที่เก็บชื่อรุ่น หรือข้อกำหนดและบันทึกข้อความเฉพาะลอตผลิตนั้นๆ (Remark)

ชื่อฟิลด์ ประเภทข้อมูล คำอธิบาย
prod_lotVARCHARหมายเลขลอตผลิตอ้างอิง
remarkVARCHARหมายเหตุรายละเอียดรุ่นการผลิต (เขียนนำออกคอลัมน์ Build Name ในรายงาน)
ตรรกะ ขั้นตอนการประมวลผลและการทำงานโดยละเอียด

การคัดกรอง DO และการระงับกลุ่ม PRB

สคริปต์เริ่มต้นอ่านข้อมูล DO ประจำวันจากฐานข้อมูล: 

$aDOdata = getDO($current_date);

วิเคราะห์คีย์นำหน้า 4 ตัวแรกเพื่อคัดแยกประเภทการขนส่ง แต่ในโค้ดมีเงื่อนไขจำกัดดังนี้:

  • กลุ่ม PRB ถูกข้ามการทำงาน: ในโค้ดควบคุม script_ftp_to_wd.php มีการปิดบรรทัดเรียกฟังก์ชันของ PRB ทั้งหมด (PRB Direct และ PRB Hub)
  • ส่งออกเฉพาะ BPI: ระบบจะเรียกใช้ฟังก์ชันเฉพาะเมื่อพบกลุ่มข้อมูล $do_bpi_direct เท่านั้น โดยส่งพารามิเตอร์ประเภทปลายทางเป็นแบบ Hub

การดึงและสืบค้นข้อมูลสายผลิตภัณฑ์ Flex

ขั้นตอนในฟังก์ชัน gen_data_and_send_file() สำหรับดึงข้อมูลสายผลิตของ Flex:

  1. getProdWMS($do_list): เชื่อมโยงใบสั่ง DO เข้ากับลอตผลิตของระบบ Flex (WMS.SHIPMENTPALLET_BOX_PROD_HTC)
  2. getShip_confirm_data($prod_lots): ดึงข้อมูลยืนยันจัดส่ง พาเลทสินค้า และชื่อที่ใช้แสดงของการส่งมอบกล่อง
  3. getPack($prod_lots): เชื่อมโยงฐานข้อมูลการผลิตของฝั่ง Hitachi (HITACHI02) โดยตรงเพื่อดึงหมายเลขรหัสแพ็กและขนาดข้อมูลบรรจุภัณฑ์
  4. getremark_in_wms_hit_fgrec_data($prod_lot): ดึงหมายเหตุข้อความจากตาราง WMS.HIT_FGREC_DATA เพื่อเตรียมระบุลงในหัวข้อคอลัมน์รายงาน Build Name

การจัดส่งข้อมูลอัปโหลดผ่าน SFTP และประวัติการบันทึก

เมื่อระบบเปรียบเทียบยอดสินค้าถูกต้อง:

  • เขียนบันทึกไฟล์: บันทึกข้อมูลออกมาเป็นไฟล์ CSV ภายในไดเรกทอรีเฉพาะบนเซิร์ฟเวอร์
  • สำรองประวัติ: สำรองไฟล์ลงประวัติ QE /file_bit_qe/
  • เชื่อมโยง SFTP: ล็อกอินเข้าใช้งานระบบคลาวด์ปลายทางของลูกค้า sftp2.wdc.com ด้วยบัญชี Belton และกุญแจเข้ารหัสความปลอดภัย Belton.ppk
  • บันทึกล็อก: ทำการเพิ่มค่าลำดับ Counter (+1) ในตาราง WMS.HIT_RUNNING_TRANSFER_CUSTOMER_FTP และเพิ่มประวัติลงตาราง WMS.HIT_TRANSFER_DATA_LOG_FTP เพื่อปิดรับ DO ที่จัดทำสำเร็จเรียบร้อยแล้ว
ส่งออก ข้อกำหนดโครงสร้างชื่อไฟล์และรูปแบบข้อมูล CSV

กฎการตั้งชื่อไฟล์ส่งออก (Filename Rule)

{Prefix}_{Type}_{YYYYMMDD}_000000_BEL_FLEX_{ModelName}_{RunningNo}.csv

ตัวอย่างชื่อไฟล์จริง: S0005_BPI_20260810_000000_BEL_FLEX_ModelY_001.csv
รหัสคีย์นำหน้าไฟล์: S0005 (กรณีคลังปลายทางแบบ Hub) หรือ Z0005 (กรณีส่งตรง Direct)
